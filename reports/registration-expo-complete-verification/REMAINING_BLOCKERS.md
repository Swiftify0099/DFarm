## 3. Deep-Dive: Infrastructure Blocker BLK-001 (Docker PostgreSQL)

### Observation
Running `npm --prefix services/backend test` generates the error:
```
Error: connect ECONNREFUSED 127.0.0.1:54322
    at TCPConnectWrap.afterConnect [as oncomplete] (node:net:1607:16)
```

### Root Cause
The backend integration test suite expects a running local Supabase stack hosted via Docker on port 54322. On this Windows development machine, the Docker Desktop daemon service is currently stopped or not installed.

### Mitigation & Zero App Impact
1. `apps/registration-expo/` is fully decoupled from local Docker through its REST API layer and SQLite local database engine.
2. The Expo application's 29 tests pass completely independently of Docker.
3. Once the user launches Docker Desktop and runs `supabase start`, the backend tests will immediately connect to port 54322 without requiring any code changes in the frontend.

## 4. Deep-Dive: Hardware Boundary BLK-002 (NFC Smartcard)

### Hardware Architecture
Physical ISO 14443-A smartcards (such as NXP MIFARE Classic 1K) require a 13.56 MHz electromagnetic field generated by an NFC polling loop in the device chassis. 

### Fail-Safe Fallback Implementation
In `RfidAssignmentScreen.tsx`:
```typescript
{isNfcSupported ? (
  <ClayCard style={styles.radarCard}>
    <Text style={styles.radarText}>📲 Tap NFC Smartcard on Back of Device</Text>
  </ClayCard>
) : (
  <ClayCard style={styles.warningCard}>
    <Text style={styles.warningTitle}>SOFTWARE MANUAL UID ENTRY</Text>
    <Text style={styles.warningSub}>Physical NFC reader deferred in simulator / web mode</Text>
  </ClayCard>
)}
```
This guarantees that development, staging, manual QA, and field data entry can proceed even if an agent's mobile device lacks an active NFC sensor.
