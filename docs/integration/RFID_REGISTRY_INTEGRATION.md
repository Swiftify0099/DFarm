## 1. Overview & Problem Remediation

Previously, the Dairy Admin RFID module exhibited two critical defects:
1. It rendered fake card UIDs (e.g. `RFID-001`, `RFID-002`) generated by in-memory mock fixtures.
2. It gave the false appearance of an active physical desktop RFID reader scanner when no reader hardware was connected.

Both issues have been remediated:
- The registry now connects directly to `rfid_cards` and `rfid_card_assignments` in PostgreSQL.
- The UI honestly displays **"Physical Desktop USB RFID Reader: Not Detected / Disconnected. Direct manual UID entry is active."** with a clear `MANUAL ENTRY MODE` indicator.

## 2. Relational Schema & Constraints

RFID management relies on two strictly normalized tables defined in `supabase/migrations/005_face_and_rfid.sql`:

```sql
-- 1. Master Card Inventory
CREATE TABLE IF NOT EXISTS rfid_cards (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE RESTRICT,
    card_uid VARCHAR(64) NOT NULL,
    card_type VARCHAR(30) NOT NULL DEFAULT 'MIFARE_CLASSIC_1K',
    status VARCHAR(20) NOT NULL DEFAULT 'UNASSIGNED',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_rfid_card_uid_per_org UNIQUE (organization_id, card_uid),
    CONSTRAINT chk_rfid_card_status CHECK (status IN ('UNASSIGNED', 'ACTIVE', 'BLOCKED', 'REVOKED', 'LOST'))
);

-- 2. Card Assignment History
CREATE TABLE IF NOT EXISTS rfid_card_assignments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    rfid_card_id UUID NOT NULL REFERENCES rfid_cards(id) ON DELETE RESTRICT,
    customer_id UUID NOT NULL REFERENCES customers(id) ON DELETE RESTRICT,
    center_id UUID NOT NULL REFERENCES dairy_centers(id) ON DELETE RESTRICT,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    assigned_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    assigned_by UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    revoked_at TIMESTAMPTZ,
    revoked_by UUID REFERENCES users(id) ON DELETE SET NULL,
    revocation_reason TEXT
);

-- Partial Unique Index: A card can only be ACTIVELY assigned to ONE customer
CREATE UNIQUE INDEX IF NOT EXISTS uq_active_card_assignment 
ON rfid_card_assignments (rfid_card_id) 
WHERE (is_active = TRUE);
```

## 3. Operational API Contracts

### 3.1 List Registered Cards
- **Endpoint:** `GET /api/v1/rfid`
- **Headers:** `Authorization: Bearer <token>`, `X-Dairy-Tenant-ID: <dairyId>`
- **Response Format:**
```json
{
  "success": true,
  "count": 1,
  "data": [
    {
      "id": "rc-00000000-0000-0000-0000-000000000001",
      "cardUid": "RFID-E2000019",
      "dairyId": "00000000-0000-0000-0000-000000000001",
      "customerId": "c1a2b3c4-0000-0000-0000-000000000001",
      "customerCode": "C-101",
      "customerName": "Suresh Tukaram Patil",
      "status": "ACTIVE",
      "issuedAt": "2026-11-16T14:40:00.000Z",
      "issuedBy": "Dairy Admin Desk",
      "lastScannedAt": "2026-11-16T17:15:00.000Z",
      "lastScannedDevice": "KIOSK_MAIN",
      "notes": "MIFARE_CLASSIC_1K"
    }
  ]
}
```

### 3.2 Assign Smart Card to Farmer
- **Endpoint:** `POST /api/v1/rfid/assign`
- **Request Body:**
```json
{
  "cardUid": "RFID-E2000019",
  "customerId": "c1a2b3c4-0000-0000-0000-000000000001",
  "operatorName": "Dairy Admin Desk"
}
```
- **Execution Flow:**
  1. Validates that the customer exists and belongs to the authenticated dairy.
  2. Upserts `rfid_cards` with `status = 'ACTIVE'`.
  3. Sets `is_active = FALSE` on any prior active assignment for this customer or card.
  4. Inserts new active record into `rfid_card_assignments`.
  5. Updates `customers.rfid_card_uid = $cardUid`.

### 3.3 Mark Card as Lost
- **Endpoint:** `POST /api/v1/rfid/mark-lost`
- **Request Body:**
```json
{
  "cardUid": "RFID-E2000019",
  "reason": "Farmer lost card during field transit",
  "operatorName": "Dairy Admin Desk"
}
```
- **Execution Flow:**
  1. Updates `rfid_cards SET status = 'LOST'`.
  2. Deactivates existing `rfid_card_assignments` with audit reason.
  3. Clears `rfid_card_uid = NULL` on the customer record so no unauthorized intake can occur.

### 3.4 Kiosk High-Throughput Card Lookup
- **Endpoint:** `GET /api/v1/rfid/lookup?uid=RFID-E2000019`
- **Latency Target:** $< 10\text{ ms}$.
- **Response Format:**
```json
{
  "success": true,
  "data": {
    "id": "c1a2b3c4-0000-0000-0000-000000000001",
    "farmerCode": "C-101",
    "fullName": "Suresh Tukaram Patil",
    "organizationId": "00000000-0000-0000-0000-000000000001",
    "status": "ACTIVE",
    "permittedCategories": ["COW", "BUFFALO"]
  }
}
```
